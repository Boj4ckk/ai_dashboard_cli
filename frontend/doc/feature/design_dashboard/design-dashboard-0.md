# Feature: Prompt to Frame — BI Canvas Dashboard
> Handoff spec for Claude Code. Read top-to-bottom before touching any file.

## Context

A BI canvas where non-technical users type natural-language prompts to populate frames with content generated by a LangGraph agent + FastMCP server. The frontend is **agnostic to chart type** — it renders whatever HTML the MCP server produces inside an `<iframe>`. The agent decides dimensions based on the frame size sent with the prompt.

---

## Architecture Overview

```
User selects frame (size locked) → types prompt → FastAPI (LangGraph agent)
  → MCP server generates HTML file at configurable asset server URL
  → backend returns { url: "https://assets.example.com/charts/abc123.html" }
  → frontend renders <iframe src={url} sandbox="allow-scripts" />
```

**Key constraint:** Frame dimensions are sent to the backend at prompt submission time. After submission the frame is locked (no resize) so the MCP-generated content matches exactly.

---

## Environment Config

Add to `.env` (frontend):
```
VITE_ASSET_SERVER_URL=http://localhost:8001
```

Used to construct iframe `src`. Pluggable — swap to any static file server without code changes.

---

## Pages & Routing

Single page: `/` renders the full canvas dashboard. No routing changes needed.

### 3. `<CanvasHost />` — `src/features/dashboard/components/CanvasHost.tsx`

Infinite pannable/zoomable canvas. Contains all frames.

**Visual:** dot-grid background via CSS `radial-gradient` on a 8000×8000px div, 24px repeat, `opacity: 0.7`.

**Interactions:**
| Input | Action |
|---|---|
| Alt + drag | Pan |
| Middle-button drag | Pan |
| Wheel (no modifier) | Pan Y |

**State (lifted to page):** `zoom: number`, `pan: { x: number, y: number }`.

### 4. `<Frame />` — `src/features/dashboard/components/Frame.tsx`

Absolute-positioned card on the canvas. 

**States:**
| State | Visual |
|---|---|
| `empty` | Dashed border `--border-strong`, `--bg-subtle`, centered placeholder text |
| `empty + selected` | Dashed border `--accent`, `--accent-subtle` bg, "TARGETED" tag |
| `loading` | Shimmer skeleton overlay (CSS animation, 1.2s ease-in-out) |
| `locked` | Solid border, normal bg, no resize handles, `<iframe>` rendered inside |
| `locked + selected` | Solid `--accent` border + `box-shadow: 0 0 0 3px var(--accent-subtle)` |

**Resize handles:** Visible only in `empty` state. 8 handles (corners + edges). Drag to resize. Min size: 200×150px. On resize, update `frame.width` and `frame.height` in parent state.

**Frame tag:** Floating pill above frame when selected — `"TARGETED"` in `empty` state, `"FRAME {n}"` in locked state. Accent bg, uppercase mono font, `font-size: 10px`.

**Close button:** top-right `×`, only visible on hover in `locked` state. Clears the frame back to `empty`.

**iframe:** rendered when `frame.status === 'locked'` and `frame.iframeUrl` is set.
```tsx
<iframe
  src={frame.iframeUrl}
  sandbox="allow-scripts"
  style={{ width: '100%', height: '100%', border: 'none' }}
  title={frame.title}
/>
```

Props:
```ts
interface FrameProps {
  frame: FrameData;
  index: number;
  selected: boolean;
  onSelect: () => void;
  onResize: (width: number, height: number) => void;
  onClear: () => void;
}
```

Types — `src/features/dashboard/types.ts`:
```ts
type FrameStatus = 'empty' | 'loading' | 'locked';

interface FrameData {
  id: string;
  x: number;
  y: number;
  width: number;
  height: number;
  status: FrameStatus;
  iframeUrl?: string;
  title?: string;
}
```

### 5. `<PromptBar />` — `src/features/dashboard/components/PromptBar.tsx`

Fixed, bottom-center. `width: min(680px, calc(100vw - 32px))`. Frosted glass, `border-radius: 16px`.

**Default state:** placeholder "Ask anything…", agent pill (idle), send button (dark, disabled).

**Targeting state** (frame selected): 
- Orange chip inside the input area: `● Frame {n}` with `×` to deselect
- Border becomes `--accent-muted`
- Send button turns `--accent` orange when `prompt.trim().length > 0`

**Submission:** enabled only when `prompt.trim()` AND a frame is selected. On submit:
1. Capture `selectedFrame.width` and `selectedFrame.height`
2. Set frame status → `loading`
3. Lock frame (no more resize)
4. Call backend API with `{ prompt, frameId, width, height }`
5. On response `{ url }` → set `frame.iframeUrl`, status → `locked`
6. On error → status back to `empty`, show error state

**Agent pill:** left side of prompt bar. Idle: subtle. Thinking: accent-subtle bg + CSS pulse animation + spinning icon. Click → opens `<AgentModal />`.

**Keyboard shortcuts:**
- `Cmd+K` / `Ctrl+K`: focus prompt input
- `Enter`: submit (if valid)
- `Shift+Enter`: newline in textarea
- `Escape`: deselect frame or blur input

**Hint bar** below input row (mono, `--text-muted`, 11px): `⌘K focus · ↵ send · Esc deselect · powered by langgraph + fastmcp`

Props:
```ts
interface PromptBarProps {
  selectedFrame: FrameData | null;
  onDeselectFrame: () => void;
  onSubmit: (prompt: string) => void;
  agentState: 'idle' | 'thinking' | 'done';
  onOpenModal: () => void;
}
```

Specular highlights: `::before` top highlight (`rgba(255,255,255,0.55)`, height 1px), `::after` inner glow.

**Content:**
- Header: "Agent thread" title + blinking `● Live` badge (only when `agentState === 'thinking'`)
- Scrollable body: conversation messages alternating user (dark bubble) / assistant (frosted bubble)
- Tool traces: each step shows `tool.name → detail` with timing. Completed steps show `✓`, active step shows blinking `·`

### 7. Backend API integration — `src/features/dashboard/api/dashboardApi.ts`

```ts
interface SubmitPromptPayload {
  prompt: string;
  frameId: string;
  width: number;   // px, integer
  height: number;  // px, integer
}

interface SubmitPromptResponse {
  url: string;      // absolute URL to generated HTML file
  title?: string;   // optional frame title suggested by agent
}

export async function submitPrompt(payload: SubmitPromptPayload): Promise<SubmitPromptResponse>
```

Base URL from `import.meta.env.VITE_API_URL` (existing). Asset server URL from `import.meta.env.VITE_ASSET_SERVER_URL`.

**Streaming traces (optional, phase 2):** SSE endpoint `/chat/stream` — each event is a `ToolTrace`. Connect on submit, close on agent done.
